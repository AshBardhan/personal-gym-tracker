# Database Setup and Management

## Overview

The backend uses **MongoDB** for persistence and **Mongoose 8** for schema definition, validation, ObjectId references, and connection management.

The `gym-tracker` database contains three collections:

- **users**: Stores user identity and creation metadata.
- **exercises**: Stores the shared exercise catalog (with embedded variants).
- **workouts**: Stores user-owned workouts with embedded exercises and sets.

Categories, target muscles, variants, and the predefined seed list are documented in [EXERCISES.md](../../EXERCISES.md).

MongoDB does not require SQL-style migrations. Mongoose creates collections when data is first written, while schema changes and data backfills should be managed as version-controlled migration scripts when existing documents need modification.

## Setup

### 1. Choose a Database

| Option | Best For | Persistence | Requirements |
| ------ | -------- | ----------- | ------------ |
| **Local MongoDB** | Local and offline development | Local disk | MongoDB Community Server |
| **MongoDB Atlas** | Team development, staging, and production | Managed cloud storage | Atlas account and network access |

**Quick Guide:** Solo offline development → Local MongoDB | Team collaboration or production → MongoDB Atlas

### 2. Configure Database

#### Option A: Local MongoDB

Install MongoDB Community Server using the official packages for your operating system, then start the service.

```bash
# Ubuntu or Debian:
sudo systemctl start mongod
sudo systemctl enable mongod
sudo systemctl status mongod

# macOS with Homebrew:
brew tap mongodb/brew
brew install mongodb-community
brew services start mongodb-community
brew services list

# Configure environment
cp .env.example .env

# Edit .env and paste the DATABASE_URL
MONGODB_URI=mongodb://localhost:27017/gym-tracker

# Verify the local server
mongosh mongodb://localhost:27017/gym-tracker
```

#### Option B: MongoDB Atlas

1. Create a cluster in MongoDB Atlas.
2. Create a database user with read and write access.
3. Add the application IP addresses to the network access list. Avoid allowing all addresses in production.
4. Copy the driver connection string and include the `gym-tracker` database name.
5. URL-encode special characters in the database password.

```bash
# Create a database on the provider's website and copy its connection string

cp .env.example .env
# Edit .env and paste the DATABASE_URL
MONGODB_URI=mongodb+srv://<username>:<password>@<cluster>/gym-tracker?retryWrites=true&w=majority
```

### 4. Initialize the Database

Seed demo data and start the API:

```bash
npm install
npm run seed
npm run dev
```

The seed command drops and recreates the `users`, `exercises`, and `workouts` collections with demo data (demo user, catalog exercises, and sample workouts).

Verify the database and collections:

```bash
mongosh mongodb://localhost:27017/gym-tracker
show collections
db.users.find()
db.exercises.countDocuments()
db.workouts.find()
```

### 5. Update Schemas and Data

For a schema change:

1. Update the relevant Mongoose model in `server/src/models`.
2. Decide whether existing documents can omit the new field.
3. Create a version-controlled migration script when existing data must be renamed, removed, converted, or backfilled.
4. Back up the database before running destructive changes.
5. Run the migration against development and staging before production.
6. Build and restart the server after the schema change.

Run a migration script with MongoDB Shell:

```bash
mongosh "$MONGODB_URI" --file migrations/<migration-name>.js
```

Build the server after updating a Mongoose model:

```bash
npm run build
npm start
```

Do not edit or rerun an already deployed migration script. Add a new migration for subsequent corrections so applied changes remain traceable.

### 6. Additional Commands

```bash
# Inspect collections and indexes:
mongosh mongodb://localhost:27017/gym-tracker
show dbs
show collections
db.users.getIndexes()
db.workouts.getIndexes()

# Back up and restore a local database:
mongodump --db gym-tracker --out ./backup
mongorestore --drop --db gym-tracker ./backup/gym-tracker

# Back up and restore MongoDB Atlas:
mongodump --uri="$MONGODB_URI" --out ./backup
mongorestore --uri="$MONGODB_URI" --drop ./backup/gym-tracker

# Count stored records:
mongosh mongodb://localhost:27017/gym-tracker --eval "db.users.countDocuments()"
mongosh mongodb://localhost:27017/gym-tracker --eval "db.exercises.countDocuments()"
mongosh mongodb://localhost:27017/gym-tracker --eval "db.workouts.countDocuments()"
```

## Schema

### User

**Collection:** `users`  
**Description:** Stores user identity for workout ownership and future authentication.

| Field | Type | Attributes |
| ----- | ---- | ---------- |
| `_id` | ObjectId | Primary identifier, generated by MongoDB unless supplied |
| `name` | String | Required, trimmed |
| `email` | String | Required, unique, trimmed, stored lowercase |
| `passwordHash` | String | Optional, excluded from default queries (bcrypt, auth not yet wired) |
| `isAdmin` | Boolean | Required, defaults to `false` |
| `createdAt` / `updatedAt` | Date | Managed by Mongoose timestamps |

**Indexes:** Default `_id` index and unique `email` index.

**Relationships:**

- One User has many Workouts through `Workout.userId`.
- One User may own custom Exercises through `Exercise.userId` when `isCustom` is true.

### Exercise (catalog)

**Collection:** `exercises`  
**Description:** Shared exercise catalog with embedded equipment variants.

| Field | Type | Attributes |
| ----- | ---- | ---------- |
| `_id` | ObjectId | Primary identifier |
| `name` | String | Required, trimmed |
| `category` | String | Required enum (chest, shoulders, arms, back, legs, core, cardio, full_body) |
| `primaryMuscleGroup` | String | Required enum |
| `secondaryMuscleGroups` | String array | Optional |
| `isCustom` | Boolean | Required; `userId` required when true, must be absent when false |
| `userId` | ObjectId | Optional reference to `User` (custom exercises only) |
| `variants` | Variant array | Required; at least one variant per exercise |
| `createdAt` / `updatedAt` | Date | Managed by Mongoose timestamps |

**Variant (embedded):** `name`, `equipment` (enum), `metrics` (array of `reps` / `weight` / `duration`, at least one).

**Indexes:** `category`, `primaryMuscleGroup`, `variants.equipment`, `{ userId, isCustom }`.

### Workout

**Collection:** `workouts`  
**Description:** Stores a workout session with denormalized exercise snapshots and sets.

| Field | Type | Attributes |
| ----- | ---- | ---------- |
| `_id` | ObjectId | Primary identifier |
| `userId` | ObjectId | Required reference to `User` |
| `title` | String | Required, trimmed |
| `date` | Date | Required, defaults to the current time |
| `memo` | String | Optional, trimmed |
| `exercises` | WorkoutExercise array | Embedded snapshots, defaults to `[]` |
| `createdAt` / `updatedAt` | Date | Managed by Mongoose timestamps |

**WorkoutExercise (embedded):** `exerciseId`, `variantId`, `name`, `category`, `primaryMuscleGroup`, `secondaryMuscleGroups?`, `equipment`, `metrics`, `sets[]`.

**Indexes:** `userId`, `date`.

### Set

**Storage:** Embedded in `Workout.exercises[].sets`  
**Description:** One logged set within a workout exercise snapshot.

| Field | Type | Attributes |
| ----- | ---- | ---------- |
| `_id` | ObjectId | Generated by Mongoose for the embedded document |
| `type` | String | Required enum: regular, warmup, drop, failure |
| `reps` | Number | Optional, minimum 0 |
| `weight` | Number | Optional, minimum 0 |
| `duration` | Number | Optional, minimum 0 (seconds) |

Volume is derived from weight (and reps when both are tracked); duration does not contribute.

### Relationship Summary

| Parent | Child | Cardinality | Storage |
| ------ | ----- | ----------- | ------- |
| User | Workout | 1:n | ObjectId reference in `Workout.userId` |
| User | Exercise (custom) | 1:n | ObjectId reference in `Exercise.userId` |
| Exercise (catalog) | Variant | 1:n | Embedded array in `Exercise.variants` |
| Workout | WorkoutExercise | 1:n | Embedded array in `Workout.exercises` |
| WorkoutExercise | Set | 1:n | Embedded array in `WorkoutExercise.sets` |
| Exercise (catalog) | WorkoutExercise | n:1 | Referenced by `exerciseId` / `variantId` (snapshot, not joined at read) |

## Troubleshooting

### MongoDB Connection Refused

Confirm that the local service is running and listening on the default port:

```bash
sudo systemctl status mongod
sudo systemctl start mongod
lsof -i :27017
```

On macOS:

```bash
brew services list
brew services restart mongodb-community
```

### Atlas Connection Timeout

- Confirm that the current client or server IP is allowed in Atlas Network Access.
- Verify the cluster is active and the hostname is correct.
- Check that the database user has access to `gym-tracker`.
- Confirm outbound access to MongoDB Atlas is not blocked by a firewall.

Test the connection directly:

```bash
mongosh "$MONGODB_URI"
```

### Atlas Authentication Failure

- Verify the database username and password, not the Atlas account credentials.
- URL-encode special characters in the password.
- Confirm the database user has read and write permissions.
- Check that `MONGODB_URI` does not contain placeholder values.

### Missing Environment Variable

Confirm that `server/.env` exists and contains `MONGODB_URI`:

```bash
cd server
ls -la .env
npm run dev
```

Do not print production connection strings in shared terminals or logs.

### Collections Are Missing

MongoDB creates collections on the first write. Seed the database and start the API:

```bash
npm run seed
npm run dev
```

Then inspect the database:

```bash
mongosh mongodb://localhost:27017/gym-tracker
show collections
```

### Duplicate Email Error

The User model enforces a unique email index. Query the existing user before creating another record with the same email:

```bash
mongosh mongodb://localhost:27017/gym-tracker --eval "db.users.find({}, { email: 1, name: 1 })"
```

### Validation Failure

- Confirm required user, workout, exercise, and set fields are present.
- Ensure `reps` is at least 1.
- Ensure `userId` and route identifiers are valid ObjectId strings.
- Review the server response and development log for the failing field.

### Schema Changes Are Not Reflected

- Restart the development server after changing a Mongoose model.
- Build the server to detect TypeScript errors.
- Remember that changing a Mongoose schema does not rewrite existing documents.
- Run the relevant migration or backfill for existing data.

```bash
npm run build
npm run dev
```

### MongoDB Shell Is Missing

Install `mongosh` separately if it was not included with the database tools:

```bash
brew install mongosh
```

On Ubuntu or Debian, install the `mongodb-mongosh` package from the official MongoDB repository.
